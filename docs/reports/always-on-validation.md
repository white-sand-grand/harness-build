# 持续任务：实现与真实 Step 验收

日期：2026-11-15。一次检查失败后，agent 读取证据并通知；定时跟进发现事实不变时保持安静；新的检查结果到达后再通知。需要修改文件时，它保存准确调用，结束本次 run，重启后等待批准再继续。

实现依据 Anthropic 的 [Building always-on agents](https://claude.com/resources/articles/building-always-on-agents)。操作见[持续任务指南](../background.md)，原理与离线示例见[第十二章](../learn/12-background.md)。本报告分别记录确定性机制检查、真实界面检查和真实模型验收。

## 真实 Step：八项核心检查通过

使用 `step-5-preview`、low 思考档位与 Anthropic 兼容接口 `https://api.stepfun.com/step_plan/v1/messages`。请求来自实际 provider，模型回复未固定；home、工作区、检查文件和项目约定均为受控临时资产。

| 检查               | 实际证据                                                    | 结果 |
| ------------------ | ----------------------------------------------------------- | ---- |
| 鉴权与模型预检     | HTTP 200，返回模型 `step-5-preview`                         | 通过 |
| 导入检查事件       | 实际 read 得到 `expected=42, actual=41`，生成一条本地通知   | 通过 |
| 定时跟进           | 再次实际 read，相同事实记为 quiet，没有新增通知             | 通过 |
| 新检查结果         | read 得到 `actual=42`，通知数变为 2                         | 通过 |
| 准确工具提案       | 修改调用保存为 suspended；批准前源文件 hash 不变            | 通过 |
| 跨进程批准         | 新进程读取同一 pending approval，再批准准确调用             | 通过 |
| 实际修改与独立检查 | 只改 `sum.js`，原 `sum.test.cjs` hash 不变，Node 测试退出 0 | 通过 |
| 空收件箱           | 没有额外 provider 调用或工具重放                            | 通过 |

检查器实际断言 `sum(19, 23) === 42`，初始结果 41，修改后结果 42。只有一次获准的修改；重复批准被拒绝。检查器 SHA-256 为 `149a542090fb422b1dc35e41ff92f1921f98d74964631764816e8008b6d27008`；最终源码 SHA-256 为 `48acf6918209bb54830373fa887db5fd3590f71cbf9c7504fe0e1a6834e7238b`。

首次修改尝试中，模型只用文字询问，没有发出工具提案，因此延期检查失败。修正 worker 的系统指令后，明确直接调用 edit/write 会由宿主先保存并挂起，并列出准确可编辑范围；未放宽权限规则。只重试该修改流程，之前失败及消耗保留。只读检查在该指令修正前完成，修改恢复检查在修正后完成；这是分阶段功能验收，不是统一版本的性能对比。

## 复验与证据边界

可复用脚本为 [always-on-step.mjs](../../test/live/always-on-step.mjs)，需要显式 `MH_LIVE=1`，凭据仅通过 stdin 进入私有 provider 内存。普通测试不调用远端。真实流程使用受控导入的 CI 数据和注入时钟，没有连接实际 CI 服务、外部消息渠道或系统开机服务。

原始失败报告、会话、数据库和截图保留为本地忽略资产；公开报告仅保留核对后的结果。离线维护进化覆盖证据门禁、候选验证与重复抑制，本轮没有单独运行真实 Step evolution，也未获得默认提示词优化收益证据。

独立只读复核确认了原始 read 结果、通知决策、唯一 edit、审批消费、检查器 hash 和全部用量，并重跑了独立 Node 检查。验收后对 441 个源码、文档、受控临时数据、日志和最终构建文件做密钥精确扫描，匹配 0、不可读 0；随后清除凭据引用并重置临时执行内核。密钥未写入配置、argv、环境变量或公开证据。
