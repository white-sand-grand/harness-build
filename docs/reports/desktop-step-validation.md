# Desktop 0.1.1：连接表单修复与真实Step验收

日期：2026-11-11。模型请求使用`step-5-preview`与Step Plan的Anthropic兼容接口；本报告的两阶段任务由真实服务完成，不使用固定模型回复。

## 配置与修复

| 字段     | Step Plan示例                                                          |
| -------- | ---------------------------------------------------------------------- |
| 协议     | Anthropic Messages                                                     |
| 模型ID   | `step-5-preview`                                                       |
| 服务地址 | `https://api.stepfun.com/step_plan`                                    |
| 认证     | 默认“直接输入密钥”，填写API Key密码框                                  |
| 环境变量 | 仅使用已有变量时选高级模式，填写如`STEP_API_KEY`的名称；不填写密钥本身 |

前后端共用字段校验：URL不能作为模型ID，服务地址和环境变量名分别给出字段错误。未提交的校验失败保留密码并定位首个错误；实际发送后清空输入。错误不回显字段内容，也不显示Electron内部传输前缀。

旧版本保存的URL模型会标记“需要修正”，可编辑但不能运行；多条错误记录可以逐条修复，不因其它未修复项阻止合法保存，不静默丢弃原数据。

依据[Step官方Messages文档](https://platform.stepfun.com/docs/zh/api-reference/chat/messages-create)，精确`api.stepfun.com`端点使用`output_config.effort=low/medium/high`；默认档位不额外指定。其它Anthropic兼容端点继续使用原预算方式，相似域名不会被误识别成Step。
