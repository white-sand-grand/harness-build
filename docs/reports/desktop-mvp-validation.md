# Desktop 0.1.0 MVP 验证

日期：2026-11-11。范围：原生Windows x64桌面MVP，使用现有mini-harness内核。UI中的执行记录、文件操作、审批与会话均来自实际程序；验收模型由本地HTTP替身提供固定响应，不调用远程付费API。

## 交付内容

- Electron45.3.0、React19.3.1、Vite8.3.8，独立Host与受约束preload；核心继续零第三方运行时依赖。
- 项目选择、JSONL会话与续接、模型/思考配置、流式文本/工具活动、审批与取消、当前工作区Git差异。
- 满月标识、月相思考动效、浅深主题与原生可访问选择控件。
- Windows NSIS安装包和免安装应用，内置Node24.22.2；首版未签名。

## GUI验收场景

1. 原生Electron启动临时中文/空格路径项目，使用真实React界面和preload。
2. 通过连接表单保存两份配置，检查密钥不落盘、能力回落与每模型深度记忆。
3. 从界面发送任务，本地SSE驱动真正的read/write，读取中文文件并写入新文件；运行中补充输入被当前run消费，改选深度不改变本轮配置。
4. Git面板同时列出既有tracked改动与untracked名称，明确是工作区全量差异。
5. 工作区外写入获本次允许后真实落盘；下一次再次询问，拒绝后文件没有创建。
6. 模型流阻塞时重载窗口，不重复请求；停止后连接关闭，任务变为取消。
7. 新建与历史会话读取真实JSONL，打开历史不重放模型或工具。
8. 重启程序后元数据和历史仍在，内存密钥已消失。
9. 额外受控桥接检查确认迟到start响应不覆盖新的模型/深度草稿，旧seq被丢弃，设置弹层不会被流式更新重建。

最新打包GUI验收仅向127.0.0.1发送7次模型请求，18次真实鼠标操作命中，渲染异常与渲染外网请求均0；两次应用均正常退出。Windows原生DPI下的截图经过PNG内容校验并实际查看，不将隐藏窗口产生的黑帧计为可视证据。

## 边界与限制

- 本地替身证明程序连接、协议和状态行为，不证明真实模型能力或第三方服务可用性；真实端点、配额与预算需由使用者配置。
- 进程监护中，一组父进程退出后子进程已提前结束，如实记录；另一组严格证明父子都存活后，私有管道EOF使两者退出，承担Job清理的因果验证。进程树回收不等于权限沙箱。
- 执行结束不等于检查通过；无检查、检查失败、中断分别显示。历史缺少完整工具详情时不伪造恢复。
- Git差异包含用户原有改动，未跟踪文件只列名称，不做自动撤销/提交/推送。
- 当前仅Windows本机、单活跃run；不包含WSL/远程执行、worktree并行、交互PTY、自动更新或桌面实验执行。
