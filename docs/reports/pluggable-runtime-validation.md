# 可组合运行时升级与验收

2026-11-10。mini-harness 增加按 profile 组合工具、上下文、记忆、提示词和 hooks 的运行时；通过独立 worker 加载外部模块，在完整运行之间切换版本。使用方式见[插件指南](../plugins.md)，可运行示例见[project-context](../../examples/plugins/project-context/main.mjs)。

## 完成的行为

| 能力         | 实现与边界                                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 组合         | tools/context/memory/prompts/hooks 按有序 ID 选择；default/clear/none 单选 reducer；offload 独立选择                               |
| 外部模块     | mh-plugin.json 显式声明入口和文件；按内容指纹先授权，复制确定版本后启动独立 worker                                                 |
| 热加载       | 新版本完整准备后替换活动快照；当前 run 和排队 steering 持有原版本，最后一个 lease 释放后关闭旧 worker                              |
| 变化检测     | --watch 在下一次完整 run 前检查文件；显式 /reload 与 /profile；损坏配置或未获批代码保留旧版本                                      |
| 上下文与记忆 | 临时 recall/context 只追加当前模型请求的 system 后缀；历史改写继续使用已有 compaction/clearing 契约；remember 完成后才记录成功终态 |
| 优化器       | PromptOptimizer 替换候选生成；候选校验、独立 gate、新鲜配对确认与 heldout 审计继续由评测层负责                                     |
| 产物采用     | recommend/unchanged 才发布版本清单；运行时显式选择，并校验整体与逐文件 hash，默认提示词不自动覆盖                                  |
| 评测隔离     | 每个 attempt 从相同冻结源码新建 worker；插件指纹与组合进入 provenance；提示词变体不改变非提示词实验条件                            |

这次实现使用自有 worker 模块契约，尚未声称兼容 MCP 或完整 Agent Plugins 规范。worker 不提供操作系统沙箱；本轮不支持插件自行使用常规 child_process/cluster 入口创建子进程，命令执行仍由内置 bash 的进程管理负责。

### 受控提示词优化与产物采用

本实验故意从 ACK-only 缺陷 prompt 开始。训练任务要求修复加法，heldout 使用独立的减法任务；每个阶段各运行两次，所有列入比较的 attempt 均正常结束、检查资产完整。

| 阶段               | 缺陷基线 | 候选 |
| ------------------ | -------- | ---- |
| dev 搜索与选择     | 0/2      | 2/2  |
| 新一轮独立配对确认 | 0/2      | 2/2  |
| 最终 heldout 审计  | 0/2      | 2/2  |

独立 gate 推荐首轮候选。第二轮没有剩余的可归因失败，返回 noChange，搜索以 `insufficientEvidence` 正常停止；保留已经确认并通过审计的候选，不继续制造修改。最终决策为 `recommend`。

优化账本记录 46 次 provider 调用（actor 39、optimizer 7），报告 token 总量 120262，用量完整；未配置价格，因此不推算费用。产物 hash 为 `f4ac4994394a36880811d84f63783a49dd6b145636b19e304e828ed9a220e2df`，12 个文件的逐项 hash 与整体 hash 均通过加载校验。

产物 reload 后，另起一个真实运行验证模型实际收到采用的 prompt，修复新工作区代码并通过 `19 + 23 = 42` 检查，检查文件保持不变。该运行另计 4 次模型调用；连同插件复验，本次有效验收共 60 次调用，连接预检单独记录。

以上证明受控缺陷下的优化、确认、审计和采用流程完成，**不能当成默认 prompt 的性能提升**。候选保留在验收产物中，没有覆盖项目默认提示词。

独立只读复核从原始结果重算了 gate、实验合同、代码与 prompt hash、检查资产及资源账本，9 组检查全部通过。候选仅修改 system.md 的通用行为描述，没有任务题名、文件名或数字答案；产物采用后的会话也确认了实际 read/write/bash 调用。
