# 07 · 把跨会话有用的信息留下来

[学习路线](README.md) · 上一章：[检查反馈](06-feedback.md) · 下一章：[能力组合](08-composition.md)

会话恢复用于接着做同一件事。项目记忆则保存以后仍可能有用的信息，例如“测试入口是什么”“这个接口为什么保留旧参数”“哪种尝试已经验证无效”。

## 从文件开始，而不是把历史全放进提示词

项目记忆位于 `MH_HOME/projects/<slug>/memory/`，与会话目录分开：

```text
memory/
├── MEMORY.md       # 简短索引：有哪些笔记、什么时候应该读
├── testing.md      # 测试入口和注意事项
└── decisions.md    # 已确认的项目约定
```

后两个文件名只是组织示例，并非程序要求。模型用普通 read/write/edit 管理笔记，用户也能直接编辑。

[readIndex](../../src/memory/memory-dir.ts) 只注入 `MEMORY.md` 的前 200 行或 25000 字节，先到者为准。详细笔记按需读取。这样保留了入口，又不会把所有历史经验反复发送给模型。

文件方案易读、容易版本管理，但没有自动语义检索。索引写得不好时，模型可能找不到正确笔记；笔记过时也不会被系统自动判定为无效。

## 普通记忆与 dream 各做什么

普通运行可以随时记录有价值的信息。Dream 则集中整理近期会话：把零散发现合并、修正冲突、精简索引。它使用同一个 agent 内核，换上专用提示词、输入和工具范围。

| 步骤     | 程序做的事                                                        | 模型做的事     |
| -------- | ----------------------------------------------------------------- | -------------- |
| 准备输入 | 默认选最近 10 个会话，渲染成 Markdown，明确列出文件路径和已有笔记 | 读取相关记录   |
| 保存起点 | 初始化独立的记忆 Git 仓库，提交已有修改                           | 无             |
| 整理     | 只提供 read/write/edit，严格限制写入记忆目录，排除 `.git`         | 组织笔记和索引 |
| 保存结果 | 提交新变化，返回前后版本和 diffstat                               | 给出整理说明   |

输入记录位于记忆仓库之外，避免把整批原始会话误当成整理结果一起提交。没有 shell 或目录工具时，模型不能靠 `ls` 发现输入，所以具体文件清单也是可用接口的一部分。

## 为什么给整理结果保留历史

记忆整理会修改将来影响模型行为的内容。独立 Git 仓库让这些变化可查看、可撤销，也与代码仓库分开。

`--dry-run` 把记忆复制到临时目录里运行，返回变更说明后清理副本。`memory undo` 只接受最新提交为 dream 结果、且记忆目录没有未提交修改的情况；用户确认后执行 revert，留下撤销记录。

当前实现即使 dream 没有正常完成，也可能保存本次产生的部分修改；调用结果保留结束原因，因此查看变化时还应检查运行是否正常结束。Git 历史提供可恢复性，并不判断笔记是否正确。

## 三种状态分别解决什么问题

| 状态       | 保存什么                 | 主要用途                   |
| ---------- | ------------------------ | -------------------------- |
| 会话历史   | 完整消息与执行记录       | 追查一次任务、恢复对话     |
| 当前上下文 | 系统提示、摘要和近期消息 | 决定下一次模型请求看到什么 |
| 项目记忆   | 经过选择的索引和笔记     | 给后续不同会话提供经验     |

摘要是为了缩短一次长对话，记忆是为了选择跨会话知识。两者都会丢弃部分细节，因此保留原始会话路径很有价值。

默认文件索引进入稳定背景，因此写入新笔记不代表已有 run 的 system 立即刷新。runtime 可以在下次 run 装入新的索引快照，也可以选择每轮读取的 file-recall 或插件记忆策略；模型主动 read 同样能读取当前文件。未启用 runtime 时，稳定 system 仍按会话对象缓存。

记忆整理保留项目经验，提示词进化验证通用执行规则。前者可以改变后续输入，后者必须在固定记忆策略和实验条件下比较；不能把召回内容变化带来的差异直接归因于候选 prompt。

## 怎样验证这一步

在项目根目录的 PowerShell 7 或 WSL Ubuntu bash 中执行：

```sh
node --import ./test/helpers/setup.ts --test test/unit/memory/memory.test.ts
```

这些测试使用临时目录、真实 Git 和固定模型回复。重点看 `memory injected into system prompt`、`bash not available to dream agent`、`writes outside memory dir denied`、`dry-run leaves real dir untouched` 和撤销确认测试。

测试能证明目录约束、版本记录和输入输出是否按要求连接，不能证明某次整理提取了正确经验。需要检验记忆效果时，应另设跨会话任务，并保留整理前后的笔记与任务结果。

源码阅读顺序：[memory-dir.ts](../../src/memory/memory-dir.ts) → [dream.md](../../prompts/dream.md) → [app/dream.ts](../../src/app/dream.ts) → [memory/git.ts](../../src/memory/git.ts)。
